## 六、这些记录反映出的真实开发决策

- 项目不是从一个固定答案直接生成，而是在医学表达、数据质量、交互复杂度与设备
  能力之间反复收缩范围。
- 开发者多次指出 AI 建议与真实 Zepp OS API 或项目约束不符。例如：
  `GRADKIENT_POLYLINE` 不应因拼写怪异被擅自更名；存储架构也不应在未获授权时
  被整体重写。
- EasyStress 是被明确使用的稳定实现参照，尤其在本地存储方面。对外说明时应如实
  披露复用或借鉴边界，并以 Git diff 和资产清单进一步区分共用模块与新增实现。
- 对外宣传必须保持“健康参考/娱乐性分析”的定位，不应把 1 Hz BPM 推导结果包装
  成医疗诊断或临床级 HRV。
