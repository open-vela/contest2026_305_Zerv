## 二、阻断项

### P0-1：尚未在当前环境完成可重现构建

执行 `npm run build` 时，`aiot-toolkit` 在进入源码编译前退出：

```text
Error: VVD directory for Vela_Virtual_Device not found
```

这说明本机工具链引用的虚拟设备目录不存在，不代表源码必然编译失败，但当前也没有
证据证明现有工作区能够干净重建。`dist/` 中虽有旧 RPK，属于被 `.gitignore`
忽略的历史产物，不能代替本次源码构建验证。

验收条件：修复 VVD 配置后执行干净构建，保存工具链版本、命令、退出码和 RPK
SHA-256；至少在赛事指定镜像和一台真机安装运行。

### P0-2：首次引导仍依赖 `@system.storage`

业务测量数据已经迁移到 `@system.file`，但 `splash` 和 `oobe` 仍通过
`@system.storage` 读写 `oobe_done`。团队此前已记录 Vela 4.0 下 local storage
不稳定，这会造成反复进入 OOBE、首次分流失败或额外申请无用 feature。

涉及文件：

- `src/pages/splash/index.ux`
- `src/pages/oobe/index.ux`
- `src/manifest.json`

建议：将 OOBE 标记也迁移到现有文件存储封装，验证成功后移除
`system.storage` feature。

### P0-3：测量过程缺少后台/中断恢复策略

测量页通过 `setInterval` 维护三分钟倒计时，并在页面显示期间请求持续亮屏。
`onHide()` 只关闭亮屏和时钟，没有保存测量起始时间或停止/恢复采集。若系统仍然
息屏、应用进入后台或页面异常隐藏，计时器和采样可能冻结，恢复后界面时间与真实
经过时间不一致。

建议：用绝对结束时间计算剩余秒数；在 `onHide/onShow` 明确选择“暂停并提示重测”
或“按时间戳恢复”；在 4.0/5.0 真机分别测试息屏、抬腕、Home 键和权限中断。

### P0-4：官方赛事日志与专属仓尚未接入

`logs/` 目前只有说明文件，没有赛事采集器生成的原始日志。Qoder、Trae 和旧
Claude Code 记录可作为迁移及前置项目的补充证据，但是否计入官方 AI Coding
工时必须以赛事支持工具、校验器和组委会规则为准。

验收条件：获得官方仓后检查仓名、分支、目录、采集器和 CI 要求；将可公开且校验
通过的原始日志按规则归档，不能人工修改或伪造格式。

## 三、高风险事项

### P1-1：算法与健康表述仍需逐屏真机核对

README 和主要结果页已有免责声明，算法文档也承认输入只是心率采样换算值。但规则
引擎仍生成“体质”“五脏平衡”和传统脉名，部分描述可能被用户理解为健康判断。

要求：

- 所有结果入口都应就近显示“科普/观察，不构成医疗诊断”；
- 不使用“检测疾病、准确率、AI 诊断、临床级 HRV”等宣传；
- 演示稿、视频旁白、应用商店描述与源码采用同一口径；
- 传统术语描述不得直接映射具体疾病或治疗方案。

### P1-2：AI 图片原始生成记录尚未补齐

`asset-register.csv` 将 6 张图片标为 Google Gemini 生成，但原始提示、生成时间、
原图和人工处理记录均为待确认。NOTICE 已避免“无第三方版权归属”的绝对表述，这是
正确方向，但提交材料仍缺可核验来源。

建议每张图片保留：原始生成图、提示或会话截图、生成日期、工具名称、裁剪/调色
说明、最终文件 SHA-256。无法确认来源的素材应重新生成或替换。

### P1-3：古籍和现代释义需要逐条来源核验

NOTICE 声称古籍引文属于公有领域、现代译写由团队负责，但资产登记仍标记“需逐条
核对版本”。应区分古籍原文、现代标点整理、白话改写和团队原创文案，避免误用现代
出版社的受版权保护整理或译注。

### P1-4：工作区存在大量未提交改动

当前 `master` 仅有两个提交，源码、文档及素材说明存在大量未提交变更，另有新增
原创性资料目录。未提交状态本身不违规，但会妨碍提交版本冻结、差异审计和问题回滚。

在获得官方仓之前不要重写历史。应先核对哪些改动属于参赛版，再形成有意义的提交，
保留 Zepp OS 前置版本与 Vela 移植的对应关系。
