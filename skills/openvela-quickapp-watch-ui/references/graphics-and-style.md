# 图形替代方案与样式禁区

> 适用：openvela 快应用（480×480 圆屏手表）。所有结论均在 `vela-miwear-watch-5.0` 模拟器实测。

---

## 一、无 Canvas 的图形替代方案

openvela 快应用组件集**没有 canvas**。自绘图形按「静态 / 动态」拆分处理。

### 1. 静态图形 → 预渲染 PNG

雷达网格、刻度盘等固定几何图形，用 Node 脚本程序化生成 PNG 资源。

- 2x 超采样抗锯齿；
- 用 `zlib` + 手写 PNG chunk 编码器即可，**零第三方依赖**；
- 改样式只需重跑脚本，几何参数与运行时组件共享同一套常量。

可直接复用的实现见本 Skill 的 `scripts/gen_radar_grid.js`。

### 2. 动态图形 → 绝对定位圆点阵

数据多边形、虚线：

- 沿线段等距铺小圆点 `div`，**仅用 `left` / `top` 定位**；
- 顶点处加大号圆点；
- `left` / `top` / `width` / `background-color` 的内联绑定 **100% 可靠**。

### 3. 曲线图 → `chart` 组件

- 折线数据密度决定平滑度：**一个正弦周期至少 30+ 采样点**；
- `axes` 设为 `display:false` 即为纯波形卡片；
- ⚠️ `datasets` **首帧不要给空数组**（异步数据就绪前先给一条平线），低版本渲染器对空数据集处理不稳。

### 4. 弧形进度 → `progress type="arc"`

- `start-angle` / `total-angle` **必须显式声明**（默认是 240° 扇形，不是整圆）；
- 顶弧样式：`start-angle="-70" total-angle="140"`。

---

## 二、`transform` 禁区（重要）

该平台 `rotate` 语义与 CSS 标准不一致且不可预测。实测三个坑：

1. **内联 `style` 绑定的 `transform` 不生效**（其他属性绑定正常）；
2. **默认 `transform-origin` 不可靠**；
3. **`rotate` 正角方向为逆时针**（与 CSS 顺时针相反）。

> **结论：任何依赖 `rotate` 的动态图形都不要做。**
> 一律走预渲染位图或圆点阵方案。静态装饰性旋转如需使用，必须显式声明 `transform-origin`，
> 并在真机 / 模拟器实测方向后再用。

**本项目实际处置**：雷达网格改为 Node 脚本预渲染 PNG，数据多边形改为绝对定位圆点阵虚线，
彻底放弃 `transform`。

---

## 三、样式禁区清单

| 禁区 | 症状 | 替代方案 |
|---|---|---|
| emoji 字符 | 渲染为豆腐块（字库无字形） | 汉字，或 PNG 图标 |
| 单边 border（`border-bottom` 等） | 画成四边整圈 | 独立的 1px 分隔线 `div` |
| 内联绑定 `transform` | 静默失效 | 静态 CSS 类，或弃用 `rotate` |
| 装饰边框图竖向平铺 | 露接缝与边框色差 | `stack` 固定底图 + `scroll` 上层滚动 |

---

## 四、数据流与组件模式

1. **子组件 `$watch` 监听 prop 不触发** → 采用「父算子渲」：
   派生计算放在**页面侧**，子组件只接收最终渲染数据的 prop
   （模板对 prop 的响应式刷新是可靠的）。
2. **需要强制刷新子组件几何**时，用 `if` 开关先降后升重建实例：
   ```js
   this.ready = false
   setTimeout(() => { this.ready = true }, 0)
   ```
